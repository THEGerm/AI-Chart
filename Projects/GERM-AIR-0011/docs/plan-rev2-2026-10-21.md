## 2. How the tool is organised

Three layers. Each one reuses the one below it.

1. **Regulation library.** Every section of every part, at every amendment level, with its effective dates, its source and a hash of the source text. Built once per part and kept. Nothing on the authority websites has to be fetched again, except to pick up a new amendment. Part 27 gets about one a year.
2. **TCDS library.** One record per TCDS: its models, and for each model the basis line by line (part and amendment, sections held at an earlier level, special conditions, exemptions, ELOS findings, exceptions). You give me the TCDS bases (the Bell 206L and Bell 407 first). The work done once on a TCDS is reused by every STC on it.
3. **STC project.** It starts from one TCDS and has:
   - **Applicability:** a main model (the 407) plus selectable models (206L, 206L-1, 206L-3, 206L-4 and so on). Each selectable model shows its deltas from the main model, highlighted.
   - **Applicable sections:** picked from the full set of the main model's basis.
   - **Elections:** compliance with an earlier amendment, section by section (Germ's GERM-AIR-0004 example: a negative slope of longitudinal stability in level flight is a case for electing an earlier amendment), and later amendments elected with their related sections (§ 5.4 of AC 21.101-1B).
   - **Exceptions, special conditions and exemptions.**
   - **Additional regulations**, for example operating rules.

**Navigation:**

- From any section, step to the previous or next amendment, or pick any two levels and see them side by side with the changes highlighted.
- From the STC, switch the model and see what moves.

**Output:** a Markdown listing per STC and model. Each row gives the section, its level, the text, the source URL and the source hash.

## 3. What the advisory material says

Rev 1 holds the full review. Only these points shape the build:

- **The basis is set per section, at a level.**
  - TC: "AWM 525.1305 Change 11", a level against each requirement (AC 521-004 § 6.6; sample table in AC 521-002 App. A).
  - FAA: "14 CFR 25 through Amendment 25-138", then exceptions, elected sections and other parts (AC 21.101-1B App. H).
  - The data model stores one row per section and level.
- **Related sections travel together** when an amendment level is elected (AC 21.101-1B § 5.4, CAR 521.158(9)). The tool flags a missing related section and never adds it on its own.
- **Each design change has its own basis** (AC 21.101-1B § 5.12). So the STC layer holds its own basis and never writes into the TCDS record.
- **AWM paragraph stamps and preamble dates differ** (525.107 stamped 2003/11/10; Change 525-9 dated 1 June 2003). Germ confirms the guess: one is the publication date and the other the effective date. The AWM ladder uses the effective date.

## 5. Architecture

```
Python fetchers (this cloud session)
   -> BigQuery dataset certbasis (project obsidian-377800)   master store
        reg_section_version   one row per section and amendment level
        reg_amendment         amendment no., effective date, FR citation
        tcds, tcds_model, tcds_basis_line
        stc, stc_model, stc_basis_line
   -> export to JSON files in AI-Chart/CertBasis/data/
   -> static web page in AI-Chart/CertBasis/ on GitHub Pages
        library browser, side-by-side diff, STC builder, Markdown export
```

- **The public page never talks to BigQuery.** A GitHub Pages site is static and public, so it can't hold a credential. BigQuery is where the data is built, checked and queried. Each data change is exported to plain JSON that the page reads.
- **STC work you do in the page** (picking sections, elections) is saved in your browser and exported as a JSON file. I commit that file to the repo. A save straight from the page would need a login, which v1 doesn't have.
- **Size:** Part 27 holds roughly 200 sections. Each section changes in a few of the 50 or so amendments, so the library is a few thousand rows (a guess until it's built). BigQuery's free tier covers 10 GB of storage and 1 TB of queries a month, so the cost should be nil.
- ⚠ **The DRS API key never goes in AI-Chart.** The repo is public. The key lives as an environment secret and is read only by the fetchers here.
